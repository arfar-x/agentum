# Implementation Plan: Knowledge base admin console

**Branch**: `ccr-9efb8e78-9y8x42` | **Date**: 2026-10-14 | **Spec**: [spec.md](spec.md)

## Summary

A Starlette service (`kb-admin`) in the existing `kb` image serves a React SPA and a JSON API.
It reads the catalog and the run history, and writes only its own configuration tables
(`sync_request`, `form_record`, `kb_source`, `kb_source_revision`) as a dedicated database role,
`kb_admin`. Everything that changes the catalog is a request the scheduler drains: the scheduler is
still the only writer and the only holder of source credentials.

## Technical Context

**Language/Version**: Python 3.12 (`kb/`), TypeScript 5.9 / React 19 / Vite 8 (`kb/frontend`)

**Primary Dependencies**: Starlette + uvicorn (already in the `mcp`/webhook stack), ruamel.yaml
(round-trip edits; new `admin` extra), psycopg 3; marked + DOMPurify for the record preview

**Storage**: the catalog's Postgres. Migration `004_admin_console.sql`: run-history columns,
`sync_request`, `scheduler_heartbeat`, `kb_source`, `kb_source_revision`, `form_record`.
`grants/admin.sql` creates the `kb_admin` grants; `make kb-init` applies them when
`KB_ADMIN_DB_PASSWORD` is set.

**Testing**: pytest with fakes (no services), `tests/integration` against Postgres (`make
kb-test`), vitest for the SPA, `tsc`, and a CI job that builds the front end.

**Constraints**: nothing in `domain/` or `application/` does I/O or names a source kind
(`tests/test_boundaries.py`); the console never holds a source credential; no response contains a
credential value.

## Constitution Check

| Principle | Check | Result |
|---|---|---|
| I. Configuration over code | No upstream component is patched. The console edits the same declarative file the scheduler reads. | Pass |
| II. Spec of record leads | Spec v2.8.0 adds §6.11 and the related rows; each flips to `done` only with the test that claims it. | Pass |
| III. Hexagonal, provable core | New use cases (`RequestSync`, `EditSources`, `ManageForms`, `DraftSummary`, `RunRecorder`) depend on ports and are proven with fakes. HTTP, SQL, ruamel and the file are adapters. | Pass |
| IV. Secrets / internal services | One new secret (`KB_ADMIN_TOKEN`, plus `KB_ADMIN_DB_PASSWORD`), generated by `scripts/generate-secrets.sh`. The service publishes a port, which this principle disallows by default: see Complexity Tracking. | Pass with justification |
| V. Least privilege | `kb-admin` has no `env_file` and no source credentials; its role cannot write the catalog (proved against Postgres). `mcp-kb` stays read-only. | Pass |
| Constraint: no new infrastructure | Same database, same image, one more container in an opt-in profile. | Pass |
| Constraint: bilingual | Titles and summaries are per-language and Persian is laid out right to left. | Pass |

## Complexity Tracking

| Departure | Why | Simpler alternative rejected because |
|---|---|---|
| `kb-admin` publishes a port (bound to `127.0.0.1` by default) | A browser has to reach it. `admin-panel` and `kb-webhook` already do the same. | Proxying it through LibreChat would give an unauthenticated write surface the same trust as chat. An SSH tunnel or a reverse proxy the operator controls is the documented way to reach it remotely. |
| The container runs as root by default | It rewrites a bind-mounted, host-owned `kb-sources.yaml` in place, as `kb-cli` already does. Capabilities are dropped except `DAC_OVERRIDE`. | Writing a sibling file and renaming would break the bind mount. `KB_ADMIN_USER` overrides it. |

## Phases (all delivered)

1. Spec rows, migration, role, compose profile.
2. Run history at both ends, heartbeat, request queue, scheduler drain (`FR-SCH-08..13`).
3. Admin app: auth, overview, runs, schedules, issues; SPA shell and views.
4. Trigger and purge/retire requests; trigger dialog and queue panel.
5. Source editing: ruamel editor, preview/apply with etag, revisions, per-kind forms.
6. Manual records: `form` source, `PresetSummarizer`, `DraftSummary`, record editor, inspector.

## Not built

Discovery candidates from the UI (the CLI's `make kb-sources-discover` covers it) and an editor
for entry overrides (`kb override` covers it). Neither is needed to manage sources or records.
